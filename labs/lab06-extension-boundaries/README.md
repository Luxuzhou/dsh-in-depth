# Lab 06：扩展机制边界消融

## 问题

同一个“生成项目质量报告”需求，分别用 Skill、MCP 工具、动态 Workflow/Subagent 和确定性领域服务表达。目标不是把机制全部用上，而是测出每一层的净收益和失败边界。

## 固定条件

固定 DSH/模型提交、仓库快照、Prompt、预算和验收 Rubric。四组实验都只能读取同一合成仓库；外部服务使用测试凭据。

## 四组实现

1. Skill：只提供审查清单和报告格式；
2. MCP：提供只读测试、覆盖率和依赖查询工具；
3. Workflow：并行启动安全、测试、架构三个 one-shot Subagent，再合并结果；
4. 领域服务：对发布门禁做确定性计算，Agent 只解释结果。

再做消融：移除 Skill、断开 MCP、限制 Subagent 深度、取消 Workflow、让领域服务返回部分失败。记录成功率、Token、时间、工具次数、权限面和错误相关性。

## 验收

报告必须指出哪些能力适合模型可选知识，哪些适合跨进程工具，哪些值得独立 Agent 上下文，哪些绝不能交给动态编排。没有证据的“更智能”不算结论。
